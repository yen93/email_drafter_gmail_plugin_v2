ASSISTANT:
Investigated (read-only). Read the full code.gs and explained the trade-off:
- onGmailComposeOpen is the compose trigger — it fires for BOTH new emails and
  replies, so the one default shows in both cases.
- The whole pipeline is reply-oriented: system prompt says "write reply drafts"
  (line 185), user prompt says "the email thread you are replying to" (line 202),
  and context comes from a Gmail thread search by recipient+subject (lines 71-81).
- On a fresh compose the recipient is usually empty when the card builds, so
  toEmail is "" (line 66), the thread search is skipped, and threadContext stays
  "No prior thread text history found." (line 70). That makes
  "Reply to the last message in this thread." actively contradictory input for an
  intro email — the model would hallucinate or produce a confused reply.
- Can't reliably branch the default text at card-build time (the compose event
  doesn't give a dependable is-reply flag before the action handler).
Recommended a neutral default that never misfires because the model already sees
whether a thread exists: "Draft a short email in James's style." Also flagged
separately that the intro flow is weak regardless of default text, since the
prompts are reply-framed — a bigger change, out of scope for a one-liner.
