PURPOSE
- Cache James Castrission's recent Gmail sample emails (SENT/DRAFT) in Supabase,
  to feed an email-drafter AI that mimics his tone/style. Emails are pulled and
  cached by an n8n workflow. A Gmail add-on (Apps Script) then reads those cached
  samples live and drafts replies in James's voice from inside the compose box.

APPS SCRIPT — MAG Gmail Assistant (Gmail add-on)
- Source copies kept in this repo (the LIVE code lives in the Apps Script project,
  not here — these .txt files are copies to paste in):
    * "MAG Gmail Assistant - code gs file.txt"      — the add-on code (code.gs).
    * "MAG Gmail Assistant - appscript json file.txt" — the manifest (appsscript.json).
- Flow: compose trigger -> onGmailComposeOpen builds an instructions card ->
  handleAiDraftGeneration gathers thread context (GmailApp.search, last 4 msgs) +
  pulls style samples from the DB -> callOpenAI (gpt-4o, Chat Completions) ->
  inserts the draft into the compose window.
- Style samples: getStyleSamplesFromDB() calls Supabase PostgREST
  (GET /rest/v1/james_email_samples, order received_at desc, limit 40), prefers
  SENT over DRAFT, strips the signature block, feeds up to 24 snippet exemplars.
  NOTE: the DB has no email bodies (payload is {"mimeType":...}), so snippets
  (~200 chars) are the only style signal available.
- Secrets/config:
    * OPENAI_API_KEY — in Apps Script SCRIPT PROPERTIES (not hardcoded). Required.
    * SUPABASE_URL + SUPABASE_ANON_KEY (publishable, read-only) — in-code constants
      (safe; the publishable key only works via the anon SELECT policy below).
- Manifest notes: urlFetchWhitelist MUST list both outbound hosts
  (https://aivitcomiywiysrfwqxt.supabase.co/ and https://api.openai.com/), else
  UrlFetchApp is blocked ("URL has not been whitelisted"). Needs scopes
  script.external_request + gmail.modify. documents.readonly is now unused (the
  old Google Doc sample source was removed) and may be dropped.

DATA STORES
- Supabase table: public.james_email_samples
  - Exists in TWO projects (identical schema):
      * MAGTestProject   — ref aivitcomiywiysrfwqxt (ap-northeast-1) — TARGET
      * n8n-production    — ref uwsncuowtzydylfabikj (ap-southeast-2) — also kept
        (n8n-production also hosts the n8n application's own DB.)
  - Columns are QUOTED to preserve exact Gmail-JSON key case so n8n "Auto-map
    input data to columns" matches 1:1:
      "id" text PRIMARY KEY (Gmail message id; natural key for dedup/upsert)
      "threadId" text            (indexed)
      "snippet" text
      "payload" jsonb            (e.g. {"mimeType": "..."})
      "sizeEstimate" bigint
      "historyId" text
      "internalDate" text        (epoch-millis string, kept verbatim)
      "labels" jsonb             (array of {id,name}; GIN-indexed)
      "Subject" text
      "From" text
      "To" text
      "Cc" text                  (nullable; absent on many messages)
      received_at timestamptz    (GENERATED from internalDate; not in JSON)
      created_at timestamptz     (default now(); not in JSON)
  - Indexes: received_at desc; threadId; GIN on labels.
  - RLS: ENABLED. n8n writes with the service_role key (bypasses RLS).
    MAGTestProject ALSO has policy "anon_read_james_email_samples" (SELECT only,
    TO anon, USING true) so the Gmail add-on can read samples with the publishable
    key. This policy is on MAGTestProject ONLY — n8n-production was left closed.

EXTERNAL INTEGRATIONS
- Gmail (OAuth2) — source of the sample emails (via n8n Gmail node) AND the host
  of the Apps Script add-on. n8n credential ref only; add-on auth via Google
  OAuth scopes in appsscript.json. No secret in this repo.
- Supabase (REST / PostgREST) — WRITTEN by n8n Supabase node (service_role, stored
  in n8n). READ by the Gmail add-on (publishable/anon key, in-code; read-only via
  the anon SELECT policy). No service_role secret stored in this repo.
- OpenAI (https://api.openai.com, Chat Completions, model gpt-4o) — called by the
  Gmail add-on to draft emails. Key in Apps Script Script Properties
  (OPENAI_API_KEY); full key file OPENAI_API_KEY.txt is gitignored.

KNOWN ISSUES / NOTES
- FIXED: PGRST102 "All object keys must match". The v1 Supabase auto-map node
  bulk-inserts all items at once; PostgREST requires identical key sets, but
  Gmail items vary (Cc present on some only). The "Normalize keys" Code node
  forces every item to the same 12 keys (missing -> null, stray -> dropped).
- OPEN: duplicate-key (23505) on repeated scheduled runs. The v1 Supabase node
  does a plain INSERT, but the schedule re-pulls overlapping message ids. Needs
  an upsert — e.g. an HTTP Request node with header
  `Prefer: resolution=merge-duplicates`, or a dedup step. Not yet implemented.
